Provider Compute API

Continuum can query and operate AWS EC2, Google Compute Engine and Azure virtual machines through the provider's supported command-line tools. These routes use the server's authenticated API and are separate from the legacy in-memory /vm/* routes.

Runtime scope

Install the relevant provider CLI on the NMC host and provide its workload identity through the service account's standard credential mechanism. Configure exact account, project or subscription identifiers in the matching allow-list:

NMC_AWS_ALLOWED_SCOPES=123456789012
NMC_GCP_ALLOWED_SCOPES=example-project-123
NMC_AZURE_ALLOWED_SCOPES=00000000-0000-0000-0000-000000000000

Provider credentials are not accepted in API request bodies. Child processes receive only the documented provider credential variables and standard configuration paths; NMC authentication secrets are not forwarded. Provider mutations are disabled by default. Enable them only after configuring scoped credentials, least-privilege provider roles, dependency checks and operational approval:

NMC_PROVIDER_MUTATIONS_ENABLED=true
NMC_PROVIDER_ALLOW_DELETE=true

Deletion requires both switches. Do not enable it for routine deployment environments. Production mutation support remains incomplete until service dependencies, durable resource inventory and host/service health verification are configured.

Routes

Method and pathPurpose
GET /providers/computeShow installed provider CLIs, allow-list configuration and mutation gates. This does not disclose scope identifiers or credentials.
GET /providers/compute/instances?provider=aws&scope=123456789012&region=eu-west-2Verify the active provider identity and return live, normalised inventory for the exact allow-listed scope. GCP accepts an optional region filter.
POST /providers/compute/instances/createCreate one instance from an explicit provider-specific network, image and size specification. AWS and GCP require a stable idempotency key.
POST /providers/compute/instances/actionRestart, start, stop or delete one exact canonical instance identifier. The active account/project/subscription, scope, region and current instance state are checked first.

Lifecycle requests

For create, send provider, scope, a provider-specific spec object and an idempotency_key. AWS requires the AMI, instance type, subnet and one or more security groups; public IP association is disabled. GCP requires project, zone, machine type, image project, image, subnet and a service account; public IP assignment is disabled. Azure requires subscription, resource group, location, image, size, administrator SSH key, virtual network, subnet and network security group; public IP assignment is disabled.

For actions, send provider, scope, canonical instance_id, action, and the required provider location (region for AWS/Azure or zone for GCP). NMC verifies provider state after the command. Host reachability, dependent service health, service-specific preflight and complete rollback are not inferred from that provider-state check.

CLI

nmc provider compute status
nmc provider compute instances --provider aws --scope 123456789012 --region eu-west-2
nmc provider compute create --provider aws --scope 123456789012 --spec-file ./instance.json --idempotency-key deployment-request-0001
nmc provider compute action --provider aws --scope 123456789012 --region eu-west-2 --instance-id i-0123456789abcdef0 --action restart

Every operation records a redacted audit event. Provider CLI output is bounded, stderr is discarded, commands use direct argument arrays rather than a shell, and each process has a fixed timeout. Configure a provider adapter only when the server runs in a controlled environment with a dedicated least-privilege identity.
